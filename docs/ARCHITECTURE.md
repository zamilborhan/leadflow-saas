# LeadFlow BD — Architecture

## Stack

| Layer      | Choice                                    |
| ---------- | ----------------------------------------- |
| Framework  | Next.js 16 (App Router), React 19, TypeScript (strict) |
| Styling    | Tailwind CSS v4 (`@import "tailwindcss"`) |
| ORM        | Prisma v8 ORM-Next (TypeScript contract authoring) |
| Database   | PostgreSQL 16 (Docker, primary store)     |
| Jobs/cache | Redis 7 (Docker: queues, jobs, caching, scheduled automation) |
| Runtime    | Docker Compose for local dev              |
| Tests      | Node built-in test runner (`npm test`)    |

## Project layout

```text
app/               Next.js App Router (routes, layouts, Route Handlers)
src/
  lib/             Shared server-side modules (env, redis client, services)
  prisma/
    contract.ts    Prisma data contract — SOURCE OF TRUTH for the schema
    contract.json  Generated by `prisma contract emit` (do not hand-edit)
    contract.d.ts  Generated types (do not hand-edit, excluded from lint)
    db.ts          Lazy Postgres client bound to the contract
tests/             Smoke/integration tests (`*.test.cjs`, `npm test`)
docs/              Product, architecture, database, development guides
docker-compose.yml Local PostgreSQL + Redis services
```

## Request flow

- UI pages are React Server Components by default; `"use client"` only where
  interactivity requires it.
- Mutations go through Server Actions or Route Handlers (`app/api/...`).
- Business logic lives in reusable modules under `src/lib/`, never inline in
  routes. Route layers validate input, check authorization, then delegate.
- External API work (Meta, WhatsApp, payments) runs in background jobs via
  Redis where appropriate; webhook handlers are idempotent with safe retries.

## Data access

- Prisma v8 uses TypeScript authoring: edit `src/prisma/contract.ts`, then run
  `npm run contract:emit`, then plan/apply a migration (`prisma migration …`).
- There is no `prisma/schema.prisma` in this project (legacy file removed).
- `src/prisma/db.ts` is the only database client entrypoint.

## Multi-tenancy (non-negotiable)

- A user belongs to one or more businesses. Every tenant-owned resource
  (leads, activities, notes, follow-ups, connections, subscriptions,
  payments, settings) carries a `businessId`.
- Business A must NEVER read or mutate Business B data: every query and every
  protected route enforces tenant isolation + authorization checks.

## Security rules

- No secrets in code, compose files, or git. Secrets come from the
  environment (`.env` locally, secrets manager in production).
- `src/lib/env.ts` is the single typed accessor; it fails fast on missing
  required vars. Never expose secrets to client components.
- Sensitive credentials stored in the database (OAuth tokens, API keys) must
  be encrypted at rest.
- Validate all external/user input; log errors without secrets or PII.
